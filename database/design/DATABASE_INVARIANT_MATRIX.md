# Database Invariant Implementation Matrix

This matrix maps every domain, relational, concurrency, and audit invariant in ECOFlow to its concrete database and application enforcement mechanism.

## Matrix Overview

| ID | Invariant | Database Mechanism | Target Tables | Timing | Lock Order | Failure Behavior | Verification Test |
|---|---|---|---|---|---|---|---|
| **A-1** | ACTIVE user must have exactly 1 primary role at commit | Deferred Constraint Trigger `trg_user_roles_validate_primary_deferred` | `user_roles` | `AFTER INSERT OR UPDATE OR DELETE DEFERRABLE INITIALLY DEFERRED` | `Users` (sorted UUID) $\to$ `UserRoles` | Transaction aborts: `Constraint violation: ACTIVE user must have exactly 1 primary role` | Assign 0 or >1 primary roles to active user; commit fails |
| **A-2** | At most 1 primary role per user at all times | Partial Unique Index `idx_user_roles_one_primary_per_user` | `user_roles` | Immediate | `UserRoles` | Unique constraint violation (`23505`) | Attempt concurrent insert of two rows with `is_primary = true` |
| **A-3** | Role reassignment locks both affected users safely | BEFORE Mutation Trigger `trg_user_roles_lock_users_before_mutation` | `user_roles` | `BEFORE INSERT OR UPDATE OR DELETE` | `Users` (`MIN(id)` then `MAX(id)`) | Serialized execution; prevents deadlocks on concurrent reassignments | Reassign role from User A to User B concurrently with B to A |
| **A-4** | User activation must validate primary role existence | Deferred Constraint Trigger `trg_users_validate_activation_deferred` | `users` | `AFTER INSERT OR UPDATE DEFERRABLE INITIALLY DEFERRED` | `Users` $\to$ `UserRoles` (read) | Transaction aborts: `Cannot set user to ACTIVE without exactly 1 primary role` | Update user status from `PENDING` to `ACTIVE` with 0 roles; commit fails |
| **A-5** | Privilege escalation prevention on role/permission assignment | Restrictive foreign keys + Admin role checks | `role_permissions`, `user_roles` | Immediate | `Users` $\to$ `Roles` $\to$ `Permissions` | Foreign key violation or HTTP 403 Forbidden | Assign non-existent permission or role; attempt assignment without `admin:all` |
| **B-1** | Active revision pointer integrity | Composite Foreign Key `fk_ecos_active_revision` referencing `eco_revisions(eco_id, revision_number)` `DEFERRABLE INITIALLY DEFERRED` | `ecos`, `eco_revisions` | `DEFERRED` at commit | `ECOs` $\to$ `ECORevisions` | Foreign key violation (`23503`): `active_revision_no` must exist for that exact `eco_id` | Attempt to point `active_revision_no` to non-existent revision or another ECO's revision |
| **B-2** | Active revision-to-header status synchronization | AFTER UPDATE Trigger `trg_eco_revisions_sync_header_status` | `eco_revisions`, `ecos` | `AFTER INSERT OR UPDATE OF status ON eco_revisions` | `ECOs` $\to$ `ECORevisions` | Automatically projects active revision status to `ecos.status` | Update active revision status; assert `ecos.status` updates in same transaction |
| **B-3** | Header status consistency guard | Deferred Constraint Trigger `trg_ecos_guard_header_revision_consistency` | `ecos`, `eco_revisions` | `AFTER INSERT OR UPDATE ON ecos DEFERRABLE INITIALLY DEFERRED` | `ECOs` $\to$ `ECORevisions` | Aborts commit: `ECO header status contradicts active revision status` | Attempt manual direct update of `ecos.status` contradicting active revision |
| **B-4** | Header pointer update auto-synchronization | BEFORE UPDATE Trigger `trg_ecos_sync_on_pointer_change` | `ecos`, `eco_revisions` | `BEFORE UPDATE OF active_revision_no ON ecos` | `ECOs` $\to$ `ECORevisions` | Automatically aligns `ecos.status` with new active revision's status | Advance `active_revision_no`; assert `ecos.status` matches new revision |
| **B-5** | ECO revision lifecycle transition adherence | Validated state machine trigger `trg_eco_revisions_enforce_lifecycle` | `eco_revisions` | `BEFORE UPDATE ON eco_revisions` | `ECOs` $\to$ `ECORevisions` | Aborts: `Invalid revision status transition` | Attempt direct jump from `DRAFT` to `APPROVED` or editing terminal states |
| **B-6** | Submitted revisions cannot be edited | BEFORE Mutation Trigger `trg_protect_eco_changes` & revision trigger | `eco_revisions`, `eco_changes` | `BEFORE INSERT OR UPDATE OR DELETE` | `ECOs` $\to$ `ECORevisions` $\to$ `ECOChanges` | Aborts: `Cannot modify ECOChange: revision status is SUBMITTED (must be DRAFT)` | Attempt to insert or update `eco_changes` after submission |
| **B-7** | ECO changes cannot move across ECOs or revisions | BEFORE UPDATE Trigger `trg_protect_eco_changes` | `eco_changes` | `BEFORE UPDATE` | `ECOChanges` | Aborts: `Security violation: ECOChange cannot be moved to another ECO or revision` | Update `eco_id` or `revision_number` on existing `eco_changes` row |
| **B-8** | Historical revisions remain immutable | Trigger rejection on terminal states | `eco_revisions` | `BEFORE UPDATE OR DELETE` | `ECORevisions` | Aborts: `Terminal revision is immutable` | Attempt to delete or modify revision after `APPROVED` / `REJECTED` |
| **B-9** | Next revision creation is atomic and concurrency-safe | Row lock on ECO header | `ecos`, `eco_revisions` | Inside transaction | `ECOs` $\to$ `ECORevisions` | Serialized: second worker sees incremented `active_revision_no` | Concurrent next revision creation attempts |
| **C-1** | Submitted revision must have exactly 1 frozen snapshot | Deferred Constraint Trigger `trg_eco_revisions_require_snapshot_deferred` | `eco_revisions`, `eco_revision_snapshots` | `AFTER INSERT OR UPDATE DEFERRABLE INITIALLY DEFERRED` | `ECOs` $\to$ `ECORevisions` $\to$ `ECORevisionSnapshots` | Transaction aborts: `ECORevision transitioned to SUBMITTED without a frozen snapshot` | Transition revision to `SUBMITTED` without inserting snapshot; commit fails |
| **C-2** | Snapshot identity references exact `(eco_id, revision_number)` | Composite Candidate Key `@@unique([eco_id, revision_number])` | `eco_revision_snapshots` | Immediate | `ECORevisionSnapshots` | Unique constraint violation (`23505`) | Attempt inserting duplicate snapshot for same revision |
| **C-3** | Submitted revision snapshot content is immutable | BEFORE Mutation Trigger `trg_reject_update_or_delete` | `eco_revision_snapshots` | `BEFORE UPDATE OR DELETE` | `ECORevisionSnapshots` | Aborts: `Table eco_revision_snapshots is strictly immutable` | Attempt `UPDATE` or `DELETE` on snapshot row |
| **D-1** | Exactly 1 formal decision per ECO revision | Composite Unique Key `@@unique([eco_id, revision_number])` | `approvals` | Immediate | `Approvals` | Unique constraint violation (`23505`) | Second approver attempts to submit approval for same revision |
| **D-2** | Standard approval governance | In-transaction database check | `users`, `ecos`, `approvals` | Inside transaction | Global hierarchy | Aborts: HTTP 403 Forbidden (not active, not assigned lead, or lacks `eco:approve`) | Non-lead or inactive user attempts standard approval |
| **D-3** | Administrative override governance | In-transaction database check | `users`, `approvals` | Inside transaction | Global hierarchy | Aborts: HTTP 403 (missing `admin:all`) or HTTP 400 (justification $< 10$ chars) | Admin override with 5-character justification |
| **D-4** | Reviewer notes required on rejection | Application schema + In-transaction check | `approvals` | Pre-validation & Transaction | Global hierarchy | Aborts: `Comments are mandatory when decision is REJECTED / CHANGES_REQUESTED` | Submit `REJECTED` decision with empty notes |
| **D-5** | Exact audit action naming | Audit Log insertion contract | `audit_logs` | Inside transaction | Global hierarchy | Rejects invalid action enum | Verify audit record action string matches approved naming |
| **D-6** | Version generation derived from frozen snapshot | Snapshot transformation function | `eco_revision_snapshots`, `product_versions`, `bom_versions` | Inside transaction | Global hierarchy | Aborts on invalid delta or transformation error | Corrupt live BOM; verify generated version matches submitted snapshot + changes |
| **E-1** | Unique scoped idempotency key | Composite Unique Key `@@unique([scope, key])` | `idempotency_keys` | Immediate | `IdempotencyKeys` | Unique conflict handled via `ON CONFLICT (scope, key) DO NOTHING` | Concurrent identical requests initiate Phase A simultaneously |
| **E-2** | Idempotency identity immutability & state machine | BEFORE UPDATE Trigger `trg_idempotency_keys_protect_identity` | `idempotency_keys` | `BEFORE UPDATE` | `IdempotencyKeys` | Aborts: `Idempotency reservation identity fields are strictly immutable` | Attempt updating identity fields or transitioning `COMPLETED` back to `PROCESSING` |
| **E-3** | Atomic lease reclamation on expired lease | Atomic `UPDATE ... WHERE status = 'PROCESSING' AND lease_expires < clock_timestamp() AND claim_token = $claim` | `idempotency_keys` | Immediate | `IdempotencyKeys` | Only 1 worker updates row (`affected_rows = 1`); others receive 423 Locked | Two workers attempt to reclaim expired lease simultaneously |
| **E-4** | Phase B row lock with real-time clock check | `SELECT ... FOR UPDATE` + `clock_timestamp()` check | `idempotency_keys` | Phase B start | `IdempotencyKeys` | Aborts: `Lease expired before exclusive row lock was acquired` | Worker delays before Phase B until lease passes |
| **E-5** | Completed reservation replay | In-transaction check | `idempotency_keys` | Phase A / Phase B | `IdempotencyKeys` | Returns stored `response_body` without executing business logic | Repeat completed request |
| **E-6** | Atomic completion in single transaction | Unified Prisma Transaction | `idempotency_keys`, business tables | Phase B commit | Global hierarchy | Complete rollback: reservation remains in `PROCESSING` if business fails | Inject failure into version release; verify reservation not marked `COMPLETED` |
| **F-1** | Atomic version counters | Exclusive row lock on `products` and `boms` (`current_version = current_version + 1`) | `products`, `boms`, `product_versions`, `bom_versions` | Inside transaction | `Products` $\to$ `BOMs` | Monotonically gapless version sequence (`COUNT(*) + 1` prohibited) | Concurrent approvals of different ECOs on same product |
| **F-2** | Product & BOM version co-location | Multi-column composite foreign keys | `boms`, `bom_versions`, `version_releases` | Immediate | `Products` $\to$ `BOMs` | Foreign key violation (`23503`) | Attempt to release BOMVersion with mismatched product_id |
| **F-3** | Version and release record immutability | BEFORE Mutation Trigger `trg_reject_update_or_delete` | `product_versions`, `bom_versions` | `BEFORE UPDATE OR DELETE` | `ProductVersions`, `BOMVersions` | Aborts: `Table is strictly immutable` | Attempt to update or delete published product/BOM version |
| **F-4** | VersionRelease lifecycle state machine | BEFORE Mutation Trigger `trg_version_releases_controlled_mutation` | `version_releases` | `BEFORE UPDATE OR DELETE` | `VersionReleases` | Aborts: `Invalid transition: SCHEDULED can only transition to RELEASED` | Attempt direct jump `SCHEDULED -> DEPRECATED` or modifying version references |
| **G-1** | Audit logs append-only | BEFORE Mutation Trigger + Revoked DDL/DML | `audit_logs`, `login_audits` | `BEFORE UPDATE OR DELETE OR TRUNCATE` | `AuditLogs`, `LoginAudits` | Aborts: `Table cannot be modified or truncated` | Run `UPDATE`, `DELETE`, or `TRUNCATE` on `audit_logs` |
| **G-2** | Least privilege database role access | PostgreSQL Role Grant configuration | `audit_logs`, `login_audits` | Engine privilege check | N/A | Aborts: Permission denied for relation audit_logs | Attempt direct audit table insert via client anon/authenticated role |
